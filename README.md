# ReqLens — линтер требований

Находит неоднозначные формулировки в ТЗ раньше, чем их найдёт разработчик: 15 правил, оценка качества 0–100, подсветка проблемных мест и Markdown-отчёт для тикета. Работает полностью в браузере, без LLM и без отправки данных на сервер.

## Зачем это нужно

Формулировки вроде «быстро», «удобно» и «при необходимости» нельзя проверить, по ним нельзя написать тест — но именно они чаще всего попадают в требования. Обычно такие места ловят на ревью или, что хуже, уже на разработке.

ReqLens делает первичную вычитку за секунды:

- вставляете ТЗ, user stories или критерии приёмки — получаете разбор на лету;
- видите, где формулировка субъективна, неполна или скрывает исполнителя;
- проверяете структуру: есть ли критерии приёмки, роль и измеримые значения;
- забираете отчёт в Markdown и прикладываете к задаче.

## Возможности

- проверка во время набора текста;
- индекс качества 0–100 и сигналы «что уже хорошо»;
- фильтр по важности: ошибки, предупреждения, подсказки;
- подсветка найденных мест прямо в документе;
- группировка однотипных замечаний, чтобы не было шума;
- три примера: плохое ТЗ, хорошее ТЗ и интеграция с API;
- загрузка `.md` / `.txt`, включая drag-and-drop;
- Markdown-отчёт: копирование и скачивание одним кликом;
- адаптивный интерфейс для телефона.

## Промо-страница

Главная страница проекта — лендинг в стиле riso (`index.html`), сам линтер доступен отдельно (`app.html`).

- локально: `http://localhost:5173/` — промо, `http://localhost:5173/app.html` — линтер;
- в production: `dist/index.html` и `dist/app.html`; кнопки на промо ведут в приложение.

## 15 правил

| Группа | Правило | Что ловит |
| --- | --- | --- |
| Неоднозначность | Скорость без метрики | быстро, оперативно, максимально |
| Неоднозначность | Оценочная формулировка | удобно, надёжно, современно, без ошибок |
| Неоднозначность | Неточное количество | несколько, часто, большинство |
| Неоднозначность | Открытый перечень | и т.д., и др., и прочее |
| Неопределённость | Неуверенное требование | при необходимости, по возможности, желательно |
| Неопределённость | Незавершённое требование | TODO, TBD, уточнить |
| Стиль | Пассивный залог | осуществляется, обрабатывается, является |
| Атомарность | «И/или» | допускает два разных поведения |
| Атомарность | Несколько требований в одном | два и более модальных глагола |
| Атомарность | Составное требование | много действий через «и» |
| Атомарность | Перечисление в одном пункте | три и более запятых |
| Дублирование | Возможный дубль | совпадение требований на 75% и более |
| Структура | Нет критериев приёмки | отсутствует раздел или Given/When/Then |
| Структура | Критерии без Дано/Когда/Тогда | есть критерии, но не в проверяемом формате |
| Структура | Не указаны роль и ценность | нет формата «Как <роль>, я хочу…» |

## Быстрый старт

```bash
npm ci
npm run dev
```

Промо-страница откроется на `http://localhost:5173`, линтер — на `http://localhost:5173/app.html`.

```bash
npm test        # тесты движка (Vitest)
npm run lint    # oxlint
npm run build   # production-сборка в dist/
npm run preview # локальный просмотр сборки
```

## Как устроено

```
src/
  linter/
    engine.ts      — парсинг требований, сигналы, оценка, сборка результата
    rules.ts       — словари и правила (термины, атомарность)
    report.ts      — Markdown-отчёт
    types.ts       — типы предметной области
    engine.test.ts — тесты движка
  components/      — интерфейс: редактор, оценка, проблемы, разметка, отчёт
  data/examples.ts — демонстрационные документы
```

- **Парсинг.** Документ разбивается на требования: списки, нумерованные пункты, маркеры `US-1`, `AC-1`, абзацы. Заголовки и названия разделов исключаются.
- **Правила.** Чистые функции со словарями стемов и регулярными выражениями. Каждое замечание содержит важность, объяснение и рекомендацию.
- **Оценка.** Штраф за замечания нормируется на число требований: ошибка — 10, предупреждение — 5, подсказка — 1.5. Итог ограничен диапазоном 0–100.
- **Интерфейс** не знает о правилах: получает готовый `LintResult` и отображает его.

Добавить правило — значит описать группу терминов или функцию и подключить её в `lint()`. Тестовый пример рядом.

## Деплой на GitHub Pages

В репозитории уже лежит workflow `.github/workflows/deploy.yml`. В `vite.config.ts` задан `base: './'`, поэтому сборка работает и из подпапки.

1. Создайте репозиторий на GitHub и запушьте код в ветку `main`.
2. В настройках репозитория: **Settings → Pages → Source: GitHub Actions**.
3. Каждый пуш в `main` будет собирать и публиковать сайт.

## Ограничения

- Это эвристики, а не замена ревью: возможны ложные срабатывания и пропуски.
- Словари ориентированы на русский язык, английские термины поддержаны частично.
- Границы требований определяются по разметке списков и абзацам, а не по смысловой модели.
- Оценка — ориентир для приоритизации, а не формальный стандарт качества.
- Данные не покидают браузер: бэкенда и внешних запросов нет.
